Architecture review · CRIS · 3 / 8

Choice 1: a static site, no server

Chosen

Static files, no build step, no packages.

Zero hosting cost; nothing to patch or secure.

Rejected

A Node and Postgres server, like the Selective Service rehearsal.

Sign-in, hosting and secrets for synthetic data only.

Price paid

One browser, one person at a time.

No real sign-in: an "Acting as" picker stands in.

Architecture review · CRIS · 4 / 8

Choice 2: rules apart from pages

Chosen

Every decision is a function in lib/.

The page never decides; it shows the answer and the reason.

Rejected

Checks written inside page scripts.

Quick to start, but only testable by clicking.

What it bought

73 unit tests in seconds.

A 16-story browser rehearsal on top.

Architecture review · CRIS · 5 / 8

Choice 3: the audit line is written in the same save

Chosen

Record and audit line saved together.

Each line carries the hash of the one before.

Rejected

Write the record, then log it.

A failure in between stores an action nobody can see.

How it shows

The Audit log page checks the chain.

"The chain is broken" names the line that changed.

Architecture review · CRIS · 6 / 8

Choice 4: working assumptions, one file each

Chosen

Required documents and closing time: content/solicitation.json.

Scoring weights: content/procurement-rules.json.

Rejected

Hard-coding the values in the rules.

Or stopping until the client supplies them.

Labelled

Every assumption is marked as a proposal on screen.

A live engagement swaps the file; the rules stay.

Architecture review · CRIS · 7 / 8

What would change my mind

Several users at once

Then a server, real sign-in and shared storage.

Real documents

Then encrypted server storage and records retention.

A Euna export

Then import responses instead of recording them.

Volume

Past browser storage limits, a database.

Architecture review · CRIS · 8 / 8

The choice I am least sure of

Browser-only storage

Right for a rehearsal on synthetic data.

Wrong the day a real response arrives.

What protects it

The rules do not know where data lives.

Moving the store is one module, tested by the same 73 tests.
